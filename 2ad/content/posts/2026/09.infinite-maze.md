Ever since I was little I have wanted to make a game with infinite
playability. I call it Infinite Maze: a pixel-art platformer in which you climb,
by torchlight, through an Egyptian tomb that goes on forever in every
direction.

The world is static. The generator derives every room from a SHA3 hash of the
seed and the room's position, so a seed always builds the same world, and every
entry in the maze connects to every other entry with probability 1.

## Climbing by torchlight

You play an explorer in a fedora who runs along corridors, climbs ladders,
walks stone stairs and jumps. The torch lights only a circle around you, so most
of the tomb sits in shadow until you reach it.

The torch is the clock. A full torch burns for 300 seconds, and its light
shrinks as it burns, to a quarter of its reach in the last tenth. A turquoise
brazier relights it to full, and an oil jar in a dead end adds 60 seconds. At
zero the torch gutters to an ember for 10 seconds, and the run ends unless you
reach a flame in that time.

![A sandstone wall fills the screen, lit gold by the torch, with a single narrow chamber cut into it. The explorer stands on a ledge beside a brass brazier burning with a turquoise flame, and a wooden ladder drops from the ledge into a dark shaft below.]({static}/images/2026/maze-brazier.png)

The generator spaces braziers so that enough flame is available to solve each
tomb, but success is not certain.

It also places hints for a lost explorer, and more of them appear as the torch
burns down. At some junctions a carved arrow high in the room points along the
way on, and about once a tomb a skeleton slumped in a lower corner points the
same way with its arm. When the torch falls below half, a second set of
skeletons fades in, so the hints thicken when you can least afford a wrong turn.
Dust is a hint too. In some dead ends it drifts back toward the way you came in,
and on the way on it hangs still, so moving dust means turn around.

The music is synthesized in the browser, a Middle Eastern scale over a frame
drum. As the torch dims it adds layers and quickens the beat, so you hear the
torch running low before you see it.

The score counts the tombs you leave through their exit doors. Every 100 tombs
earn a rank, and what the ranks are is yours to find out over a lifetime of
solving. Coins lie in dead ends and in rows of three along corridors, and they
lure you into dead ends while the torch burns.

## Phone, controller or keyboard

The game runs in the browser and plays on a phone, a gamepad or a keyboard, so a
link is all a friend needs to start climbing. Up or down takes the ladder or
stair in the cell you stand in from anywhere on its floor, so a thumb on glass
is precise enough to climb.

## Save codes

A save is the seed code and one integer, such as `K7Q2-M9XA:4813`, which packs
the signed coordinates of a room into one number. Every room is a pure function
of the seed and its position, so you can type the code on another device and
resume in the same room. A climb started on a laptop at lunch carries on from
the phone on the way home.

![The pause screen over a dimmed tomb. CONTINUES 0 and TOMB 0 flank the word PAUSED at the top, a small map of the tomb fills the middle with an orange marker for the explorer, and the save code QZKA-HWDB:0 MEDIUM shows in turquoise below it, above the keys P RESUME, ARROWS PAN, Q TITLE, M MUTE and C COPY.]({static}/images/2026/maze-pause.png)

P pauses and shows the map of the passages you have walked, with the save code
under it, and C copies the code. The game also keeps your last save in local
storage, so after a reload CONTINUE? picks up where you stopped.

A code holds coordinates below 2²⁵ rooms in each direction. A room takes six
seconds to run across, so walking that far sideways in a straight line would
take about six years, and the maze winds.

## A world defined by static rules

A seed is 8 Crockford base32 characters. Every random value in the game comes
from one SHA3-256 hash of the seed, a tag and some coordinates, so each value
stands alone and the generator can build any room in any order, a million tombs
up included, and get the same answer. Generation uses integer arithmetic only,
so a seed builds the same world on every JavaScript engine.

Both scales of the world follow one rule, a tree that joins all the doors. A
board is one room, a 12×7 grid of cells. A tomb is a grid of boards, and tombs
tile an unbounded plane. Inside a board the cells form a spanning tree:
horizontal links become corridors, vertical links ladders and diagonal links
stone stairs, and the rest is rock.

Each tomb has one exit door, up, left or right, picked by a hash of the tomb's
position, so following exits from tomb to tomb only climbs or moves sideways. A
tomb has an entry door wherever a neighbour's exit opens into it, so up to three.
Both boards on a shared wall read the same hash for the door's position, so the
doors line up whichever board the generator builds first, even hours apart.

## One tree, pretty much for sure

Every corridor in Infinite Maze belongs to one tree, and that tree has no end.
Only a finite piece of it can ever be checked, so it is worth saying which parts
rest on construction, which on probability and which on tests.

### Certain, whatever the hash says

The maze is trees nested inside trees. The cells of a room form a tree, rooms
join through single doors into a tree for each tomb, and tombs join through
their exit doors. A tree has exactly one path between any two of its points, so
wherever you stand there is exactly one way to anywhere else, and every dead
end you walk into is a branch of that one way.

Suppose a loop of tombs existed. To close, it would have to come back down or
circle within a row. Exits only climb or move sideways, so it can't come back
down. Within a row the sideways exits are one-way steps along a line, and a line
of one-way steps never returns to where it started. So the loop can't exist.

These rules hold for every value the hash can return, because the hash only
chooses among moves the rules allow. A broken hash could make a dull maze, but
it would still be a maze with no loops, doors that line up on both sides of
every wall and one path between any two cells.

### Almost sure, if the hash flips fair coins

The way up leans on the hash behaving like fair coin flips. A walk from tomb to
tomb climbs whenever its tomb exits up, and otherwise steps sideways. A walk
that runs 100 tombs sideways before it climbs has odds near one in 2<sup>100</sup>,
and a walk that never climbs has probability 0.

The joins rest on the same model, since two tombs share a tree only when their
walks upward merge. In each row each walk drifts left or right before it climbs,
so the gap between two walks wanders like a drunkard on a line. George Pólya
proved in 1921 that a random walk on a line or a plane returns to its start with
probability 1, and that in three dimensions it may wander off for good. Shizuo
Kakutani put it as "a drunk man will find his way home, but a drunk bird may get
lost forever." The gap between two walks is a drunk man. It closes, the walks
merge, and from there they climb together, so every tomb joins the one tree.

Pólya's theorem has a sting in it. The expected time to come home is infinite,
so a meeting can come absurdly late. On seed 0000-0000 the walks from tombs
(0, 0) and (10, −50) are 15 columns apart at row 0 and first meet at row
773,851. At a tomb a minute, climbing that far takes a year and a half without
sleep, for two tombs that started a few screens apart.

For any one seed the hash has already fixed every wall, so two walks either meet
or they don't. The probability lives in the fair-coin model, where walks that
never meet have probability 0, the way an endless run of tails has probability 0
for a fair coin. Mathematicians call that almost surely.

### SHA3 is not a coin

SHA3-256 is a real function with 2<sup>256</sup> outputs. Two given inputs
collide with probability 2<sup>−256</sup>, and over a lifetime of play, a
trillion hashes or so, the chance of even one collision is near
2<sup>−177</sup>. A collision would change nothing you could see, since the
no-loop rules hold for every value the hash returns. Odds like 2<sup>−177</sup>
and 2<sup>−100</sup> are past the point where probability means anything in
practice: a billion tries a second since the Big Bang adds up to about
2<sup>88</sup>.

### Every room has a twin

A room is built from a finite number of choices, so the generator can build only
finitely many rooms. The maze holds infinitely many, so by the pigeonhole
principle some room has to repeat, whatever the hash. In the fair-coin model the
claim gets stronger: rooms far apart read independent hashes, so every room the
generator can build turns up again, almost surely, infinitely many times over.
So does every tomb, and every neighbourhood of tombs around it.

The number of possible rooms is too many to count, too many to play and too many
to remember, but fun to think about. A lifetime of play, a room every six
seconds for eight hours a day over fifty years, reaches about 90 million rooms.
The twin of the room you stand in sits unreachably far away, opens onto
different neighbours and changes nothing about the one tree. Then we have a good
challenge here. Find a room and its twin.

### What the tests check

Construction covers the shape and probability covers the way up and the joins,
so the tests check that the code builds what the argument assumes. A harness
runs the generator from the game's own source over 2,121 tombs, columns −10 to
10 by rows −50 to 50, at each of the four difficulties. It checks SHA3-256
against the FIPS 202 vectors and rebuilds every connection from the doors on both
sides of each wall, without trusting the generator's own bookkeeping. It follows
every exit walk out of the window, then climbs from tomb (0, −50) to the exit
door at row 50. A fixed seed has to produce a fixed digest, so the world built
today is the world built tomorrow.

This is not a machine-checked proof. The joins rest on a model of the hash, and
the tests cover a finite window of an infinite plane. That proof would make a
good paper.
