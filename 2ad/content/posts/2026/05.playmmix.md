An MMIX playground, [playmmix](https://playmmix.2ad.com), puts an MMIX machine
in your browser with no install, no local setup, no build step.

MMIX is Knuth's 64-bit RISC architecture. I built
[checksmix](/checksmix-fast-mmix-emulator.html) to assemble and run programs for
it. playmmix wraps that same engine with an editor and a live debugger, in Rust,
Yew and WebAssembly.

Editing the source re-assembles and reloads the machine at its entry point, the same
way `mmixdb` does — but nothing executes until you click Run.

![playmmix in action]({static}/images/2026/playmmix-prime.gif)

## Driving the MMIX machine

Five controls drive execution:

- **Run** executes until the program halts or hits a breakpoint.
- **Step** executes one source-level step, following calls into the callee.
- **Step Over** runs a call until it returns, unless a breakpoint or halt stops it first.
- **Stop** interrupts execution where it is.
- **Reset** reloads the current source, clearing output and change highlights.

Click a line number to set a breakpoint on an instruction. The machine pane
highlights values that changed since the previous pause. Step once and see
what moved; run to a breakpoint and see what changed along the way.

## Testing a small prime

Trial division tries D = 2, 3, 4, … against N. If D divides N, N is composite.
If D·D exceeds N first, N is prime.

`IsPrime` is a subroutine, so Step and Step Over have visibly different jobs:
Step enters it, and Step Over runs the whole search at once.

Paste this into playmmix:

```nasm
        LOC     #100
Main    SETL    $1,97            ; N
        PUSHJ   $0,IsPrime
        TRAP    0,Halt,0         ; result in $0: 1 prime, 0 composite

IsPrime CMPU    $1,$0,2
        BN      $1,Composite     ; 0 and 1 are not prime
        SETL    $1,2             ; D
Loop    MULU    $2,$1,$1
        CMPU    $2,$2,$0
        BP      $2,Prime         ; D * D > N
        DIVU    $2,$0,$1
        GET     $2,rR            ; N mod D
        BZ      $2,Composite
        ADDU    $1,$1,1
        JMP     Loop
Prime   SETL    $0,1
        POP     1,0
Composite SETL  $0,0
        POP     1,0
```

`SETL` loads a 16-bit constant, so N stays below 65536 and D·D stays well
inside 64 bits.

Click **Run**. The program halts with `$0 = 1`: the loop tries 2 through 9 and
stops at 10, since 100 exceeds 97. Change 97 to 91 and run again: `$0 = 0`,
found at 7. The answer lives in the register; the halt message's exit code is a
separate value, left at zero in both cases.

## Following the call

Put 97 back and click **Reset**. One click on **Step** loads N into `$1`. The
next instruction is `PUSHJ $0,IsPrime`.

Click **Step** again. Now we're at `IsPrime`, call depth is 1, and N is in `$0`.
The register number changed because the call moved the register window. The
caller stages arguments just above the register named by `PUSHJ`; the callee
sees them starting at `$0`.

Set a breakpoint on `Loop` and click **Run**. D is in `$1`: 2. Each **Run**
stops at the top of the next pass, with D climbing while N stays put, until
10·10 passes 97 and the branch goes to `Prime`.

Now **Reset**, **Step** once and choose **Step Over** on the `PUSHJ`. Execution
still stops at `Loop`, because Step Over respects breakpoints inside the call.
Click the line number to remove the breakpoint and **Run**: `IsPrime` returns
and the program halts. With no breakpoint set, a single Step Over runs the
whole search and pauses at the `TRAP`.

## Getting home

`PUSHJ` writes the return address to the special register `rJ`. `IsPrime`
calls nothing, so `rJ` survives untouched. `POP 1,0` returns one value, placing
the callee's `$0` in the register `Main` named in its `PUSHJ`, which is also
`$0`. The [MMIX instruction reference](https://mmix.cs.hm.edu/doc/instructions-en.html)
has the full register-stack rules.

## Under the hood

checksmix is the assembler and the emulator with registers,
memory and TRAP handling. Playmmix uses its public `MMixAssembler` and `MMix`
APIs. The editor, execution controls and machine display live in playmmix.

Re-assembly pauses for half a second after typing stops, so an unfinished line
doesn't flash an error on every keystroke. Run and Step flush any pending edit
before executing. A successful assembly starts a fresh machine.

Step Over doesn't skip the call. It single-steps through the callee
automatically, checking the call depth after every instruction until execution
returns to where it started. That's also why a breakpoint set inside the callee
still fires even under Step Over: the same per-instruction check Run relies on
applies here too.

Long runs execute in bounded chunks, yielding to the browser between them.
That keeps Stop available, including while Step Over is working through a
call. The arithmetic runs locally in WebAssembly.

For `.mmo` object files or a shell, use
[checksmix](https://github.com/jac18281828/checksmix), also available on
[crates.io](https://crates.io/crates/checksmix). Its command-line debugger,
[mmixdb](/mmix-debugger.html), has its own worked example.
